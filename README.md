# parcelhub

包裹站点交接台账：本机运行的命令行工具，仅依赖 Go 标准库，数据保存在本地 JSON 文件，无需任何外部服务。

- **收件登记（register）**：单件登记，包裹编号在数据文件内唯一，成功后状态为“在站”并产生一条收件记录。
- **查询（query）**：按编号展示当前站点、当前状态、当前未解除异常（若有）及按提交顺序排列的完整轨迹；交接记录带请求号，出站记录带批次号与配送员，回执记录带批次号、结果、原因（失败时）与请求号，冻结记录可辨认异常单号、原因、站点和时间，解除冻结记录带异常单号、解除请求号与处理说明。
- **站点交接（handoff）**：一次提交多件包裹。实物完成移交后包裹直接归属目的站点（仍为“在站”），每件各追加一条交接记录。只能交接在站包裹。
- **整批退回（return）**：按原交接请求号把整批实物送回该交接的源站点。批次与站点取自原交接结果，不可另选包裹或目的站；每件按提交顺序追加一条退回记录，原收件、交接轨迹保留不变。
- **配送出站（dispatch）**：一次提交一个配送批次（批次号 + 出发站 + 配送员 + 非空且无重复的包裹集合）。首次出站要求全部包裹已登记、在出发站且状态为在站，任一不满足整批拒绝；成功后整批转为“配送中”（站点仍记出发站），每件追加一条含批次、配送员和时间的出站记录。批次成员按首次提交顺序保存，不可修改。
- **逐件回执（receipt）**：按请求号对批次内一件包裹提交签收或失败。失败必须给出清理后非空的原因，签收不可带原因。签收后状态为“已签收”；失败表示实物已回到出发站，恢复“在站”，可加入新的配送批次。每件在一个批次只能成功回执一次；全部成员回执后批次自动完成。
- **回执整批导入（receipt-import）**：从本地 JSON 文件一次导入多条回执（可涉及多个配送批次），按文件顺序处理。只有全部记录可接受并整体保存后才报告成功；任一记录无效、冲突或受理条件不符，整份拒绝并提示记录位置与原因，新请求号均不占用，可纠正后重试。与逐件 receipt 共用同一回执请求号去重范围。
- **批次查询（batch）**：按批次号展示原成员、配送员、出发站、出站时间、逐件回执与未回执项，以及批次是否完成；批次不存在时报错。
- **异常冻结（freeze）**：对在站包裹登记异常冻结，输入异常单号、包裹编号、所在站点和原因。成功后站点不变、状态为“异常冻结”，追加冻结记录；一件包裹同时只能有一张未解除异常单，配送中或已签收包裹不能冻结。冻结期间，包含该包裹的首次交接、配送出站或整批退回须整批拒绝；冻结只是管理记录，不移动实物、不算新流转。
- **解除冻结（unfreeze）**：输入解除请求号、异常单号和处理说明。成功后包裹在原站恢复“在站”，原异常单永久标记为已解除（不可复用），追加解除记录；异常单不存在、已解除或对应关系不符均拒绝，之后可用新异常单再次冻结。
- **批次中止（abort）**：输入中止请求号、批次号和原因，表示配送员已将该批次全部尚未回执的包裹实物收回出发站。成员与站点取自原批次结果，不允许另选成员或站点。首次中止要求批次存在、尚未完成且未中止，且至少有一件未回执成员；这些成员必须仍在原批次配送中、归属出发站，任一不符整批拒绝。成功时按原成员顺序将全部未回执件恢复“在站”，各追加一条含批次、中止请求号、原因、站点和时间的收回记录；收回不是失败回执。已回执成员及其回执完全保留，即使它们已进入其他批次或被冻结也不阻止中止。中止永久关闭原批次，原成员顺序、配送员与出站时间保留不变；每批只能成功中止一次。
- **中止去重**：中止请求号独立去重，可与批次号、包裹号及其他业务编号同名。同号、同批次和清理后同原因重放，返回首次收回集合与时间，不重新计算成员、不检查当前状态、不改写台账；换批次或原因报冲突；失败的首次中止不占号。收回件可交接、冻结或再次出站，但不能首次回执旧批次（receipt 与 receipt-import 同样遵守，导入含迟到回执时整份拒绝）；收回算新流转，不能因此退回出站前的旧交接。
- **异常单与解除请求号去重**：异常单号标识一次异常，解除后也不能复用；同号、同包裹、同站点和清理后的原因重放返回首次冻结结果与时间，不再次冻结，同号换内容报冲突，失败冻结不占号。解除请求号独立去重，可与异常单号、包裹号及其他业务编号同名；相同请求号、相同异常单及清理后的处理说明重放返回首次解除结果与时间，不检查当前状态，换内容报冲突，失败解除不占号。
- **请求号去重**：请求号与包裹编号相互独立。同一请求号 + 相同源/目的/包裹集合（集合顺序无关）重复提交，直接返回首次成功结果、不再追加轨迹；请求号相同但业务内容不同报冲突；失败的首次提交不占用请求号。
- **批次号去重**：批次号标识一次配送，完成后也不能复用。同批次号 + 同站点 + 同配送员 + 同包裹集合（顺序无关）重复出站，返回首次出站结果及时间、不改变当前进度；同号换内容报冲突；失败的出站不占用批次号。
- **回执去重**：回执请求号单独去重，可与批次号、包裹号、交接或退回请求号同名。同请求号 + 同批次、包裹、结果和清理后的原因重放，返回首次回执结果及时间，不改变状态、轨迹或批次进度，也不检查当前状态（即使失败包裹已进入新批次）；换内容报冲突；失败的提交不占号。
- **退回去重**：退回请求号与交接请求号分属独立去重范围，允许同名。相同退回请求号 + 相同原交接 + 相同原因重复提交，返回首次退回结果、不追加轨迹，即使包裹之后又被交接也照常重放；换原交接或原因报冲突；失败的首次退回不占用请求号。每个原交接只能成功退回一次。
- **流转约束**：首次交接和退回只能操作在站包裹；配送出站和回执都算新的流转，之后不能退回此前的旧交接；已有交接、退回的同内容重放仍返回旧结果，不移动包裹。冻结与解除只是管理记录，不移动实物、不算新流转：冻结期间包含冻结包裹的首次交接、配送出站或整批退回整批拒绝，其余成员不变；解除后若没有其他新流转，原本可退回的交接仍可整批退回，发生过新的交接、退回、出站或回执后仍不能退回旧交接；已有交接、退回、出站及回执的同内容重放在冻结期间也返回历史结果，不移动包裹或解除冻结。
- **一致性**：一次成功操作的包裹状态、轨迹、批次进度和去重结果作为一个整体原子落盘；任何业务校验失败或读写失败都不留下部分变更，原有有效数据保持不变。数据文件不存在时自动建立空台账；已有内容损坏时明确拒绝读写（退出码 1），不会当作空库覆盖。

## 环境

Go 1.24 或更新版本，无第三方依赖。

## 运行

```sh
# 直接运行
go run . --help

# 或构建为二进制
go build -o parcelhub .
./parcelhub --help
```

## 用法

数据文件可用全局 `--data` 或各子命令的 `--data` 指定（默认 `./parcelhub-ledger.json`）。

```sh
# 1) 单件收件登记
parcelhub --data ledger.json register --id P001 --station 站点A
parcelhub --data ledger.json register --id P002 --station 站点A

# 2) 按编号查询（当前站点、状态、完整轨迹）
parcelhub --data ledger.json query --id P001

# 3) 一次提交多件包裹的站点交接（--parcel 可重复）
parcelhub --data ledger.json handoff \
  --request R1 --from 站点A --to 站点B \
  --parcel P001 --parcel P002

# 4) 按原交接整批退回（实物送回该交接的源站点）
parcelhub --data ledger.json return \
  --request RT1 --handoff R1 --reason 错发站点

# 5) 配送批次出站（--parcel 可重复；整批转为“配送中”）
parcelhub --data ledger.json dispatch \
  --batch B1 --station 站点B --courier 张三 \
  --parcel P001 --parcel P002

# 6) 逐件回执：签收或失败（失败必须给原因）
parcelhub --data ledger.json receipt \
  --request RC1 --batch B1 --parcel P001 --result 签收
parcelhub --data ledger.json receipt \
  --request RC2 --batch B1 --parcel P002 --result 失败 --reason 收件人不在

# 7) 批次查询（成员、配送员、出站时间、逐件回执进度、是否完成）
parcelhub --data ledger.json batch --id B1

# 8) 回执整批导入：从文件一次导入多条回执（可涉及多个批次）
parcelhub --data ledger.json receipt-import --file receipts.json

# 9) 在站包裹异常冻结（冻结期间禁止交接、出站与整批退回）
parcelhub --data ledger.json freeze \
  --incident E1 --parcel P001 --station 站点B --reason 外包装破损

# 10) 解除异常冻结（原站恢复在站；异常单永久标记为已解除）
parcelhub --data ledger.json unfreeze \
  --request U1 --incident E1 --note 已核实放行

# 11) 配送批次中止（未回执包裹全部收回出发站，批次永久关闭）
parcelhub --data ledger.json abort \
  --request A1 --batch B1 --reason 车辆故障全部收回
```

回执导入文件为有序且非空的 JSON 数组（文件只读，不会被修改），每条记录提供
请求号、批次号、包裹编号、结果（签收/失败）及失败原因（失败时必填）：

```json
[
  {"request": "RC1", "batch": "B1", "parcel": "P001", "result": "签收"},
  {"request": "RC2", "batch": "B1", "parcel": "P002", "result": "失败", "reason": "收件人不在"}
]
```

导入的受理与去重规则：

- 每条记录的请求号、批次号、包裹编号、结果去除两端空白后不可为空；失败须给清理后非空的原因，签收不可带原因；文件内请求号清理后不可重复。
- 按文件顺序处理。首次回执要求批次存在、包裹属于该批次、尚未在该批次回执，且当前仍在该批次配送中；每件在一个批次只能成功回执一次，同文件换请求号再次回执同一批次同一包裹也会整份拒绝。
- 与逐件 receipt 共用同一回执请求号去重范围（与其他业务编号独立；文件路径或文件名不作为去重身份）：同请求号且批次、包裹、结果、清理后的原因相同的记录返回首次结果与时间，不检查当前状态、不追加轨迹、不改变批次进度，即使包裹随后进入新批次或被冻结也成立；换内容报冲突。单件提交的结果能从文件重放，文件提交的结果也能用 receipt 重放；相同内容换文件或重排记录不会再次生效。
- 整份导入只有全部记录可接受并整体保存后才报告成功，按文件顺序列出各条结果、发生时间及新增或重放标记；任一记录无效、冲突或受理条件不符，整份拒绝并提示记录位置与原因，此次新增的包裹变更、轨迹、批次回执和请求结果全部撤销，新请求号均不占用，可纠正后重试；全部为历史重放时不改写台账。

冻结期间 `query` 会额外显示当前未解除异常，轨迹中同时保留冻结与解除冻结记录：

```
  1. 操作: 收件    ...
  2. 操作: 交接    站点: 站点B    请求号: R1    时间: ...
  3. 操作: 冻结    站点: 站点B    异常单号: E1    原因: 外包装破损    时间: 2026-10-05 16:05:22 +0800
```

冻结与解除的受理条件：

- 冻结：包裹已登记、在指定站点且状态为在站；配送中、已签收或已有未解除异常单的包裹不能冻结；异常单号、包裹编号、站点、原因去除两端空白后均不可为空。
- 解除：异常单存在、尚未解除，并且仍是该包裹当前冻结对应的异常单；解除请求号、异常单号、处理说明去除两端空白后均不可为空。
- 冻结、解除失败时不占用异常单号或解除请求号，原有数据不变；冻结与解除只是管理记录，不移动实物、不算新流转。

退回的受理条件（首次提交时整批校验，任一不满足则整批拒绝、不作任何改动）：

- 原交接存在且尚未成功退回；
- 批次中每件包裹仍归属原交接目的站、状态为在站；
- 每件包裹最后一条流转记录就是该原交接——包裹经其他交接又回到同一站点的，不能退回旧交接；请求重放不算新的流转。

退回成功后 `query` 的轨迹中会展示退回记录（源站、目的站、时间、原因、退回请求号、被退回的原交接请求号）。

### 去重与冲突

```sh
# 同请求号、同内容、包裹集合换序：返回首次结果，不追加轨迹
parcelhub --data ledger.json handoff --request R1 --from 站点A --to 站点B \
  --parcel P002 --parcel P001
# -> 交接成功（请求号重复提交，返回首次保存的结果，未再追加轨迹）

# 同请求号但源/目的/集合任一不同：冲突报错，已有结果不变
parcelhub --data ledger.json handoff --request R1 --from 站点A --to 站点C --parcel P001
# -> 状态码 1：请求号 "R1" 已用于一次不同的交接……内容冲突
```

即使包裹后来已移交其他站点，同内容重放仍返回首次保存的结果，不重新检查首次的源站条件。退回同理：相同退回请求号、相同原交接与原因的重放返回首次退回结果，即使包裹之后又被交接也不重新检查；同一退回请求号换原交接或原因则报冲突。已退回的原交接仍保留原成功结果，其 handoff 请求同内容重放照常返回首次交接结果，不会重新移动包裹。

冻结与解除遵循同一套重放规则：

```sh
# 同异常单号、同包裹、同站点、同原因（两端空白清洗后）：返回首次冻结结果与时间，不再次冻结
parcelhub --data ledger.json freeze --incident E1 --parcel P001 --station 站点B --reason 外包装破损
# -> 冻结成功（异常单号重复提交，返回首次保存的结果，未再追加冻结记录）
# 异常单解除、包裹随后流转后重放仍是首次结果；同号换包裹/站点/原因则报冲突

# 同解除请求号、同异常单、同处理说明：返回首次解除结果与时间，不检查当前状态
parcelhub --data ledger.json unfreeze --request U1 --incident E1 --note 已核实放行
```

异常单号与解除请求号分属独立去重范围，二者及与包裹号、交接/退回/回执请求号、批次号都允许同名；冻结/解除失败均不占号。

## 退出码

| 码 | 含义 |
|---|---|
| 0 | 成功；无参数、`-h`、`--help` 显示帮助也为 0 |
| 1 | 业务校验失败（重复登记、包裹不存在、交接或退回条件不满足、冻结或解除条件不满足、请求冲突等）或数据文件读写失败 |
| 2 | 未知命令或未知参数（提示输出到标准错误） |

## 数据文件

默认为当前目录下的 `parcelhub-ledger.json`，可通过 `--data` 指定任意路径（目录不存在会自动创建）。写入采用“临时文件 + 原子替换”，避免崩溃留下半份数据。
